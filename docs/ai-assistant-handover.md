# Handover to an AI engineering assistant

**Audience:** the collaborator's AI assistant or C++ developer.

## Inputs required

- The complete Integration Specification generated by the Sinilab.ai website.
- The collaborator's own plugin source code and existing build/installer instructions.
- Supported 3ds Max versions and a lawful way to access matching Autodesk SDK dependencies.
- Access to the **approved** Sinilab.ai Native Licensing SDK release when published. The public documentation alone is not enough to compile a working integration.

## Work sequence

1. Inspect the existing plugin and build; preserve its Class_ID, functionality, UI, version support and current installer where possible.
2. Read the Integration Specification; use its exact WooCommerce SKU as the Product Code. Do not use the Create Cube demo SKU.
3. Determine whether the selected type is **Host Only** (no Sinilab.ai licensing integration) or **Host + Sinilab.ai Licensing**.
4. For Host + Licensing, use the real public SDK interface; enforce entitlement before each protected operation. Do not invent APIs or implement a separate Bridge client.
5. Build against the correct Autodesk SDK; prefer the collaborator's existing build pipeline. GitHub Actions is optional.
6. Keep the collaborator's Windows EXE installer, or prepare an approved branded installer if needed.
7. Validate installation, activation, licensed operation, revocation, network interruption, recovery, removal and reinstall.
8. Supply the final installer and release notes; exclude secrets, SDK development material and internal tests.

## What not to do

Do not automatically reactivate a released licence; do not silently consume a new seat. Do not edit the shared Plugin Licensing application or Bridge. Do not imply that a historical example is production-approved. Ask for missing SDK release files rather than guessing APIs.
